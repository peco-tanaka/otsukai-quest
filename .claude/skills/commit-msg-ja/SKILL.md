# commit-msg-ja

stagingにある変更差分のみを対象とする

## ワークフロー

1. `git diff --staged` を実行してステージングの変更内容を取得する
2. 変更を分析してコミットメッセージを以下のフォーマットで提案する

## フォーマット

```
<type>: <件名（日本語）>
- <変更点1>
- <変更点2>
```

- 件名は変更の要旨を簡潔に（20文字以内目安）
- 箇条書きは変更内容に応じて柔軟に調整（1〜5個程度）
- 箇条書きは具体的な変更内容を記述する

## typeの選び方

| type | 使いどき |
|------|---------|
| feat | 新機能の追加 |
| fix | バグ修正 |
| docs | ドキュメントのみの変更 |
| refactor | リファクタリング（機能変更なし） |
| test | テストの追加・修正 |
| chore | ビルド・設定・ツール類の変更 |
| style | コードフォーマット（動作変更なし） |

複数のtypeにまたがる場合は、最も主要な変更のtypeを選ぶ。

## 例

```
feat: バトルシステムの怒り状態を実装
- BattleManagerに怒り状態の遷移ロジックを追加
- 怒り状態中のコマンド制限をCommandButtonUIに反映
- BattleEnumsにAngerStateを追加
```
